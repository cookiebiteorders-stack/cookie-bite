================================================================================
     AUTOMATED CONFIRMATION & NOTIFICATION SYSTEM — FULL IMPLEMENTATION PROMPT
     Order Confirmation | Payment Confirmation | Invoice Creator |
     Email Notifications | WhatsApp Notifications
================================================================================

You are a senior full-stack engineer. Build a complete, production-ready
automated notification and document generation system for an e-commerce or
business admin dashboard. This system must be integrated into both the backend
(API/server) and the frontend (admin dashboard + customer-facing pages).

The system covers five core pillars:
  1. Order Confirmation
  2. Payment Confirmation
  3. Invoice Generation (PDF)
  4. Email Notification System
  5. WhatsApp Notification System

================================================================================
SECTION 1 — SYSTEM ARCHITECTURE OVERVIEW
================================================================================

FLOW:
  Customer Places Order
        ↓
  Backend receives order → saves to DB → triggers Order Confirmation event
        ↓
  Payment is processed → triggers Payment Confirmation event
        ↓
  Invoice is auto-generated (PDF) → stored + linked to order
        ↓
  Email is sent to customer (order details + invoice attachment)
        ↓
  WhatsApp message is sent to customer (summary + order tracking link)
        ↓
  Admin dashboard shows real-time notification of all events

TECH STACK (adapt to your existing stack):
  Backend:   Node.js (Express) OR Python (Django/FastAPI) — specify yours
  Database:  PostgreSQL OR MongoDB
  Email:     Nodemailer + SMTP (Gmail / SendGrid / Mailgun)
  WhatsApp:  Twilio WhatsApp API OR Meta (Facebook) Cloud API
  PDF:       PDFKit (Node.js) OR WeasyPrint/ReportLab (Python)
  Queue:     Bull (Node.js) OR Celery (Python) for async job processing
  Frontend:  React / Next.js OR any existing frontend framework
  Storage:   Local disk OR AWS S3 / Cloudinary for PDF invoices

────────────────────────────────────────────────────────────────────────────────
3A. ORDER CONFIRMATION MODULE
────────────────────────────────────────────────────────────────────────────────

TRIGGER: Fired automatically when a new order is saved with status "confirmed".

LOGIC:
  1. Validate order exists and has all required fields.
  2. Generate a unique, human-readable order number if not already assigned:
       Format: ORD-{YEAR}{MONTH}-{PADDED_ID}   e.g. ORD-202505-00142
  3. Update order status to "confirmed".
  4. Log the event in notification_logs.
  5. Dispatch async jobs: EMAIL_JOB + WHATSAPP_JOB + INVOICE_JOB.

ENDPOINT:
  POST /api/orders
  Body: { customer_id, items: [...], shipping_address, notes, coupon_code }
  Response: { success: true, order: { id, order_number, total, status } }

  POST /api/orders/:id/confirm   (manual confirm from admin)
  Response: { success: true, message: "Order confirmed and notifications sent." }

3B. PAYMENT CONFIRMATION MODULE
────────────────────────────────────────────────────────────────────────────────

TRIGGER: Fired automatically when a payment record is saved with
         status "completed". Also fires when a payment webhook is received
         from your payment gateway.

LOGIC:
  1. Receive payment confirmation (from gateway webhook or manual entry).
  2. Find linked order → update order payment status.
  3. Save payment record to payments table.
  4. If payment is first successful payment for order → trigger invoice
     generation + send payment confirmation email + WhatsApp.
  5. Log in notification_logs.

WEBHOOK ENDPOINT (for payment gateways):
  POST /api/webhooks/payment
  Headers: { X-Signature: "<gateway_signature>" }   ← always verify this
  Body: gateway-specific payload (Stripe, PayMob, Fawry, etc.)

  Internal handler:
    - Verify webhook signature
    - Extract order reference + amount + status
    - Call internal confirmPayment(orderId, paymentData)

MANUAL PAYMENT ENDPOINT (for cash/bank transfer):
  POST /api/payments/manual
  Body: { order_id, method: "bank_transfer", amount, reference_number, paid_at }
  Response: { success: true, payment_id, invoice_url }

WHATSAPP SEND FUNCTION (Meta Cloud API — Node.js):
  async function sendWhatsApp(phone, templateName, parameters) {
    const response = await fetch(
      `https://graph.facebook.com/v18.0/${process.env.WHATSAPP_PHONE_ID}/messages`,
      {
        method: 'POST',
        headers: {
          'Authorization': `Bearer ${process.env.WHATSAPP_TOKEN}`,
          'Content-Type': 'application/json'
        },
        body: JSON.stringify({
          messaging_product: 'whatsapp',
          to: phone,                     // format: "201012345678" (no +)
          type: 'template',
          template: {
            name: templateName,
            language: { code: 'en_US' },
            components: [{
              type: 'body',
              parameters: parameters.map(p => ({ type: 'text', text: p }))
            }]
          }
        })
      }
    );
    const data = await response.json();
    await logNotification({ channel: 'whatsapp', status: data.messages ? 'sent' : 'failed' });
    return data;
  }

PHONE NUMBER FORMAT:
  Always strip the + sign and any spaces/dashes.
  Egypt:    +201012345678  →  "201012345678"
  UAE:      +971501234567  →  "971501234567"
  Validate format before sending using a phone normalization library.

SECTION 4 — ASYNC JOB QUEUE SETUP
================================================================================

Never send emails or WhatsApp messages synchronously in the order creation
request — this will slow down the API response and fail if the notification
service is down.

Use a job queue to handle all notifications asynchronously.

QUEUE SETUP (Node.js — Bull + Redis):
  npm install bull ioredis

  const Queue = require('bull');
  const notificationQueue = new Queue('notifications', {
    redis: { host: process.env.REDIS_HOST, port: 6379 }
  });

  // Add jobs to queue
  notificationQueue.add('order_confirmation', { orderId: order.id }, {
    attempts: 3,          // retry 3 times if it fails
    backoff: { type: 'exponential', delay: 5000 }
  });

  // Process jobs
  notificationQueue.process('order_confirmation', async (job) => {
    const order = await getOrderWithDetails(job.data.orderId);
    await sendOrderConfirmationEmail(order);
    await sendOrderConfirmationWhatsApp(order);
  });

  notificationQueue.process('payment_confirmation', async (job) => {
    const order = await getOrderWithDetails(job.data.orderId);
    await generateInvoice(order);
    await sendPaymentConfirmationEmail(order);
    await sendInvoiceEmail(order);
    await sendPaymentConfirmationWhatsApp(order);
    await sendInvoiceWhatsApp(order);
  });

JOB TYPES:
  - order_confirmation      → email + whatsapp
  - payment_confirmation    → email + whatsapp + trigger invoice job
  - invoice_generation      → generate PDF, upload, save URL
  - invoice_delivery        → email (with PDF attached) + whatsapp (with URL)
  - shipping_update         → email + whatsapp
